# 配置边界说明

本文档用于明确项目中的三类信息分别应该放在哪里，避免把环境变量、站点固定资料和数据库内容混在一起维护。

## 一、环境变量：`.env` / `.env.example`

适合放“随部署环境变化”或“敏感”的信息：

- `DATABASE_URL`
- `REDIS_URL`
- `NEXTAUTH_SECRET`
- `NEXTAUTH_URL`
- `SITE_URL`
- 上传目录、上传大小限制
- AI Provider、API Key、Base URL
- 仅用于初始化的管理员账号种子配置

原则：

- 环境变量不承载站点正文内容
- 环境变量不承载首页、页脚、关于页这类文案
- `.env.example` 只放模板和占位值，不放真实密钥

## 二、站点固定资料：`src/config/site.ts`

适合放“全站固定、公开展示、通常不需要后台维护”的资料：

- 品牌名和简称
- 站点默认描述
- 首页 Hero 固定文案
- 页脚固定文案
- 公开邮箱
- GitHub 链接

原则：

- 这类信息属于程序级公开配置，不属于数据库内容
- 修改后应直接随代码生效，不依赖后台发布流程
- 如果未来明确需要交给运营人员在后台维护，再单独设计站点设置系统，不要提前数据库化

## 三、数据库内容：后台可管理

适合放“属于内容、需要后台维护、改完希望前台直接生效”的数据：

- 文章
- 分类
- 标签
- 友链
- 单页内容，例如 `about`

原则：

- 只要前台页面读取的是数据库内容，就必须给后台提供对应管理入口
- `seed` 只负责初始化默认数据，不负责后续持续维护
- 初始化内容应明确标注为占位数据，避免误以为要继续通过 seed 更新

## 当前项目的实际约定

- 关于页正文：数据库 `Page`，后台“单页管理”维护
- 友链：数据库 `FriendLink`，后台“友链管理”维护
- 品牌名、公开邮箱、GitHub、首页和页脚固定文案：`src/config/site.ts`
- 站点访问地址：`SITE_URL`

## 判断规则

拿不准该放哪时，按下面判断：

1. 这个值会不会随部署环境变化，或者是否属于密钥？
   结论：放 `.env`

2. 这个值是不是全站固定资料，而且不打算交给后台维护？
   结论：放 `src/config/site.ts`

3. 这个值是不是内容，且希望后台可编辑？
   结论：放数据库，并补后台管理能力
